# Эксплуатация PostgreSQL

Royal Casino хранит только учебные виртуальные кредиты. Здесь нет денежных средств, депозитов, выплат или платёжных провайдеров.

## Запуск и проверки готовности

Создайте `.env` из `.env.example`, замените `DB_PASSWORD` и задайте случайный `JWT_SECRET` минимум 32 байта. Затем `docker compose up --build`; compose ждёт здоровую PostgreSQL 16, применяет миграции отдельным сервисом и запускает API только после успешного завершения миграций.

`GET /api/health` проверяет только процесс. `GET /api/health/ready` проверяет PostgreSQL и возвращает 503, если БД недоступна. Чтобы вручную проверить graceful shutdown, выполните `docker compose stop api`, затем `docker compose logs api` и убедитесь, что есть `graceful shutdown complete`; Kubernetes/Compose должен дать контейнеру не менее 15 секунд на завершение.

Для production используйте отдельного пользователя PostgreSQL с минимально необходимыми правами, TLS перед публичным ingress, сетевые ACL и шифрованное хранилище backup. `LOG_LEVEL` настраивается; заголовки Authorization, cookie, password, refresh token и API key редактируются в JSON-логах.

## Резервные копии

Установите PostgreSQL client tools (`pg_dump`, `pg_restore`), задайте DB_* переменные в `.env` или окружении, затем выполните:

```sh
npm run db:backup
npm run db:backup -- ./secure-backups/royal-casino.dump
```

Храните копии вне Git и сервера приложения, шифруйте хранилище и применяйте срок хранения по политике организации. Для учебной среды делайте копию перед миграциями и регулярно (например, ежедневно) при наличии ценных данных.

## Проверка восстановления

Восстановление очищает совпадающие объекты целевой БД. Выполняйте его сначала на отдельной тестовой БД с суффиксом `_test`, заданной переменной `DB_NAME`. Подтверждение обязательно:

```sh
# Убедитесь, что DB_NAME указывает на отдельную БД, например royal_casino_test.
DB_RESTORE_CONFIRM=YES npm run db:restore -- ./secure-backups/royal-casino.dump
NODE_ENV=test npm run db:migrate:status
NODE_ENV=test npm run test:integration
```

В PowerShell задайте `$env:DB_RESTORE_CONFIRM = 'YES'`, выполните восстановление и удалите переменную после команды. Успешная проверка восстановления означает, что миграции и интеграционные сценарии выполняются на восстановленной копии; периодически фиксируйте длительность и результат.

## Очистка устаревших записей

`npm run maintenance:cleanup` удаляет refresh-токены, срок которых истёк более 30 дней назад, и аудит старше `AUDIT_RETENTION_DAYS` (по умолчанию 365, допустимо 30–3650). Запускайте планировщиком после проверки политики хранения и резервного копирования.
