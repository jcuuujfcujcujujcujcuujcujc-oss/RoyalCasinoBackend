# Отчёт о доработке RoyalCasinoBackend

**Объект:** RoyalCasinoBackend — учебный backend каталога казино-игр и виртуальных кредитов  
**Основа:** существующая модульная архитектура Node.js, Express 5, Sequelize 6 и PostgreSQL  
**Критерии:** лабораторная № 3 «Авторизация и безопасность Backend» и предыдущие присланные лабораторные по ревьюированию и расширению проекта.

## Результат

Проект расширен на базе существующего кода, а не создан заново. Добавлены регистрация игроков и вход, JWT Access Token, ротируемые Refresh Tokens, роли ADMIN/MANAGER/PLAYER, контроль доступа к собственному профилю, административное управление ролями и блокировками, транзакционный AuditLog, поиск, ограничения пагинации, HTTP-защита и Swagger/OpenAPI. Существующие casino-маршруты и алиасы сохранены; ранние миграции не переписывались.

Проект по-прежнему использует только виртуальные кредиты. Реальные денежные операции, платежи, ставки и игровой движок не добавлялись.

## Реализованные изменения

### Аутентификация и пользователи

- `POST /api/auth/register` проверяет email, никнейм и длину пароля в байтах, сохраняет bcrypt-хеш, назначает только PLAYER и транзакционно создаёт связанный Player и стартовый профиль кредитов.
- `POST /api/auth/login`, `/refresh`, `/logout`, `GET /me` выдают и проверяют токены.
- JWT подписывается только HS256 с проверкой алгоритма, срока, issuer и audience; конфигурация секретов вынесена в окружение.
- Refresh Token генерируется криптографически случайно, хранится в БД только как SHA-256 хеш, отзывается и ротируется под блокировкой строки.
- Добавлен административный bootstrap, берущий пароль из временных переменных окружения; встроенного пароля и секрета в коде нет.

### Роли и доступ

| Роль    | Доступ                                                                                |
| ------- | ------------------------------------------------------------------------------------- |
| PLAYER  | Публичное чтение каталога, собственный профиль и собственный виртуальный баланс       |
| MANAGER | Управление играми и категориями, список игроков и статистика                          |
| ADMIN   | Полный доступ, удаление игр/категорий, роли, блокировки, список пользователей и аудит |

Защищённые запросы проверяют активность пользователя и актуальные роли из БД. Отключённым пользователям отзываются Refresh Tokens; чужой профиль скрывается ответом 404. Регистрация не принимает роль, статус активности или хеш пароля от клиента.

### Миграция и аудит

Добавлена аддитивная миграция `20260401000000-add-auth-audit.js`: таблицы `users`, `roles`, `user_roles`, `refresh_tokens`, `audit_logs` и nullable unique-связь `players.user_id`. Роли создаются миграцией. Старые игроки остаются с `user_id = NULL` и продолжают существовать.

Аудит записывает регистрацию, вход, обновление токена, игровые и категорийные CRUD-операции, CRUD профиля игрока, блокировку и назначение ролей. Критические операции и запись события выполняются в одной транзакции. В details нет паролей, токенов или адресов email. API журнала доступен только ADMIN и предоставляет фильтры по пользователю, действию, типу объекта и диапазону дат. Изменение журнала через API не предусмотрено.

### Списки, HTTP-защита и документация

- Поиск с ограничением длины добавлен для игр, категорий и игроков; фильтры и сортировки используют Sequelize-операторы и белые списки.
- `page` и `limit` проверяются как строгие целые числа; limit ограничен 100, максимальное смещение — 1 000 000 записей; сортировка стабильна с дополнительным `id`.
- Подключены Helmet, ограничение JSON до 100 KB, общий rate limit (300 запросов/IP за 15 минут), отдельные лимиты входа (5/15 минут) и регистрации (10/15 минут), настраиваемый CORS.
- Swagger UI опубликован на `/api/docs`, JSON-спецификация OpenAPI 3 — на `/api/openapi.json`; описаны Bearer-схема и основные операции.
- Обновлены `README.md` и `docs/API.md`, добавлены инструкции конфигурации и безопасного создания первого администратора.

## Остаточное условие перед защитой

Задать локальные DB-параметры и секрет `JWT_SECRET` (случайное значение минимум 32 байта), применить миграции в тестовой БД, создать администратора через `npm run admin:bootstrap`, затем выполнить `npm run test:integration`. В `.env.example` оставлены только шаблонные значения; рабочие секреты в репозиторий не добавлялись.

## Этап 1 аудита и модернизации

- Admin-модуль разделён на routes/controller/service/validation; добавлен `distinct: true` для корректного подсчёта пользователей с несколькими ролями.
- Security headers, CORS, rate limits и CSP Swagger вынесены в `src/middleware/`; inline-проверка изменения профиля заменена именованным middleware, динамические `require` удалены.
- Добавлены ESLint flat config и Prettier, npm-скрипты `lint`, `format`, `format:check`; метаданные пакета приведены к `royal-casino-backend`, MIT и GitHub repository.
- Добавлена проверка передачи отклонённых Promise Express 5 в общий error handler и unit-проверки admin validation.
- `npm run test:unit`: 68/68 PASS. `npm test`: 68 PASS, 36 integration SKIP из-за отсутствия отдельной PostgreSQL `_test` базы. `npm run lint`, `npm run format:check`, `npm audit`: PASS (0 vulnerabilities).
- Madge проверил 53 исходных файла: циклических зависимостей не найдено. depcheck сообщил только `pg` и `pg-hstore`; это ложные срабатывания для Sequelize PostgreSQL dialect, они намеренно сохранены.
- Docker и PostgreSQL в текущем окружении недоступны; DB integration и миграции не запускались.

## Этап 2 — безопасность

- Добавлены `TRUST_PROXY` (по умолчанию отключён) и `ENABLE_DOCS` (выключена по умолчанию в production); production отклоняет шаблонный пароль БД.
- Login rate limits учитывают только ошибки и применяются по IP и нормализованному email. Требует проверки на общем store при нескольких экземплярах приложения.
- Добавлена миграция refresh-token семейства (`family_id`, `replaced_by`), ротация внутри транзакции, отзыв семейства и audit при повторном использовании, endpoint `POST /api/auth/logout-all`.
- Заглушка bcrypt создаётся при старте с настроенным `BCRYPT_ROUNDS`. MANAGER получил чтение любого профиля игрока/кредитного профиля; не-ADMIN не может менять email через Player PATCH.
- Изменены интеграционные сценарии повторного использования, logout-all и запрета изменения email. `npm run lint`, `npm run test:unit` (68 PASS), `npm test` (68 PASS, 37 SKIP из-за отсутствия PostgreSQL), `npm run format:check` и `git diff --check` прошли.
- Миграция refresh-семейств, PostgreSQL integration, brute-force с реальным store и поведение через доверенный reverse proxy не проверены: PostgreSQL и прокси в среде отсутствуют.
